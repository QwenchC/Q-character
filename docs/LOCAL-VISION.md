# 本地视觉结构检查

Windows 0.10.1 / Android 0.7.1 共用此功能。先初检，再结合原图与局部对照图独立复核，区分疑似结构差异、正常透视、遮挡／不可见和证据不足。它是辅助检查，不能保证发现所有差异。

## 本机准备

1. 启动电脑上的 Ollama。当前这台电脑已安装支持视觉的 `qwen3.6:35b-a3b`，无需再下载权重。在生成服务设置中可填写其它**已经安装、支持 vision 的本地 GGUF** 名称。实际能力由 Ollama `/api/show` 校验；拒绝 cloud 标签、远程模型和无视觉能力的模型。
2. 将 Release 中 `QCharacterVision-node.zip` 解压，里面的整个 `QCharacterVision` 文件夹放到 `ComfyUI/custom_nodes/`。开发环境也可运行 `npm run vision:install -- F:\ComfyUI-aki\ComfyUI`。更新会备份同名旧文件，不改 ComfyUI 核心、不自动安装依赖或下载模型。
3. 空闲时重启 ComfyUI，让新节点生效。在应用中检查连接，确认没有提示缺少 `QCharacterVisionReview`、`JoinImageWithAlpha` 或 `LoadImage`。

2026-10-17 已确认这台电脑的日常 ComfyUI 加载 `visibility-v2`，Windows 与 Android 经原外网地址的检查、标记、确认后局部重绘和复检已完成。实测发现小选区删除结构时重绘不足，0.10.1 / Android 0.7.1 已同步修复。视觉节点与 0.10.0 相同，已完成这次重启的用户无需再次安装节点或重启。应用仍会在上传前拒绝旧节点。见 [新版完整流程与原外网实测](vision-v2-remote-validation/REPORT.md)；此前的 [准确度样例](vision-accuracy-validation/REPORT.md) 和 [0.9.1 验证](remote-vision-validation/REPORT.md) 保留为历史记录。

## 使用步骤

1. 在多视图设计中指定已抠图的正面、背面和至少一个侧面。先确认轮廓，原始透明通道会参与检查，透明背景合成白底后送入模型。
2. 点击“运行本地视觉检查”。推理由电脑执行；手机沿用 ComfyUI 的内网或穿透连接、认证和已有证书授权。无需暴露 Ollama 端口。
3. 查看四类统计，展开“全部复核依据”检查对应部件、双方可见性、透视／遮挡解释和数量单位。“查看对应区域”显示目标黄色定位框与正面蓝色参照框（提供参照框时）；疑似结构差异另显示红框及重绘建议。所有坐标相对于各自原图，缩放与手机换行不改变标记位置。
4. 建议和核对说明可修改，点击“保存建议与说明”后随作品保存。认为是正常遮挡或设计差异时填写原因，再选“合理差异／无需修正”。“模型自评”不是经过校准的正确率。
5. 需要修正时点击“确认建议并调整选区”。这一步只保存接受状态、打开画布，**不生成图片**。模型框会转换为带软边的初始选区；用画笔扩大、缩小或擦除，检查参考图并编辑要求。框可能偏移，数量差异可能涉及多个分离部件，请把实际要修正的位置都涂选。
6. 点击“开始局部重绘”才提交 Qwen 工作流。只合成选区内结果，保留原图、选区、前景蒙版和新版本。0.10.1 起对选区完整重新采样，避免强行保留要删除的结构；应只涂选需要修改的区域，生成后仍可能有修补痕迹。视图槽位使用新抠图后，旧视觉报告自动过期；重新检测新版本，再确认本次结果。
7. 未发现明确差异也需点击“已核对标记及不确定项，确认本次检测”。已开始视觉检查但未确认，或报告过期，会阻止这组多视图生成 3D。旧版颜色检查若已开始，也需完成它的逐项核对。

## 同步与恢复

报告绑定素材编号，包含观察、可见数量、不确定项、坐标、建议、确认状态和对应任务；新版还保存每个候选的独立复核、原始判定、降级原因和两轮耗时。它们和设计图、蒙版、GLB、调色方案一起双向同步。历史报告保存在对应任务中，新检测不会删除旧记录。两端同时修改同一报告时保留冲突副本，不按最后修改时间覆盖。建议或核对说明有未保存编辑时，同步会等待完成编辑。两端均需升级；旧版不能读取 version 2 报告，拒绝导入以免丢失复核证据。新版仍可读取 version 1 历史。

手机网络断开或重启后，可按原任务编号“继续接收”，不重新提交推理。更换服务器后需切回原地址。取消只删除本任务队列项；支持定向中断的 ComfyUI 会同时中断本任务。旧服务器不发送全局中断。

## 实现与资源

自定义节点只访问固定的 `http://127.0.0.1:11434`，禁用环境 HTTP 代理，不接受外部 Ollama 地址，不拉取模型。图片经手机到 ComfyUI 后，由同机 Ollama 处理。节点在 ComfyUI 队列中执行，先释放该进程持有的生成模型显存，再运行视觉推理；新加载的视觉模型完成后卸载，原已加载模型保留其原有缓存策略。其它独立进程占用的显存需要自行释放。

图像最大边缩至 1024，保持长宽比；单图坐标归一化到 0–1000。第一轮最多 6 项候选，第二轮始终执行（包括零候选），附局部对照图辅助检查。必须复核每项候选，也可补充漏检。只有双方清晰、部件对应、其它解释已排除、非单纯二维轮廓、给出正面参照框的差异才能成为重绘建议。数量差异还要求同一单位、明确且不同的数量；自相矛盾的证据降为待核对。没有按口袋、鞋子或配饰名称直接屏蔽问题。

使用非思考输出、固定采样参数和 JSON Schema，但仍需验证完整类别覆盖、合法框和数值；缺失或截断的报告会显示失败，绝不退回颜色判断后宣称视觉通过。原图文字和生成建议均作为数据处理，不执行其中的指令。每次运行重新推理。两轮会增加耗时，也可能降低召回；不能将“没有重绘建议”解释为“设计一致”。

模型仍可能幻觉、漏检、标记过宽/偏移，尤其面对遮挡、细小首饰或大透视。推荐正交或小透视的全身设计图；检测框只提供画笔起点。
