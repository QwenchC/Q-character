# 局部重绘融合与修补痕迹复核验证

2026-10-17，Windows 0.11.0 / Android 0.8.0（versionCode 10）。本次目标为减轻局部重绘色差和圆形接缝，并区分表面痕迹与真实部件。以下为小样本功能验证，不是视觉准确率或生成成功率基准。

## 使用方式与升级

两端更新后，局部重绘自动使用新版融合；无新增选项。查看“全部复核依据”与“修正前后与选区”，对照原图，再确认本次检测。确认重绘建议只打开选区，点击“开始局部重绘”才生成；痕迹分类不会自动确认或自动重绘。

安装 Release 的 `QCharacterVision-node.zip`，整个 `QCharacterVision` 文件夹放在 `ComfyUI/custom_nodes/`，空闲时重启 ComfyUI。此电脑已通过安装脚本备份旧文件并安装新版，**还需重启日常 ComfyUI**。新版客户端要求 `repair-aware-v3`；节点保留旧 `visibility-v2` 输入默认值以兼容旧工作流。手机不需要额外穿透 Ollama 端口。

当前报告 version 3 绑定当前图、直接父图和实际选区的不可变编号；Windows、Android 原生存储和同步均校验这些引用。新版继续读取 version 1 / 2 历史。两端均应升级，旧客户端不能读取 version 3。

## 融合改动与同候选对照

旧流程先在服务端按蒙版合成，再在客户端按同一蒙版混合一次，会重复衰减软边。现在服务端仍用稳定合成图估计前景 alpha，但正式输出保留原始生成 RGB，由客户端融合一次。

客户端在有可靠不透明周边参照时，按分离选区分别估计小幅 RGB 偏移；只在相近材质内校色。对原本平坦、低对比且与选区过渡方向相符的边缘减轻接缝，不按圆形形状抹除物体。复杂纹理、强对比部件、透明边缘及整图选区采取保守处理，选区外 RGBA 不变。

使用同一个真实 Qwen 生成候选及相同 alpha，对照旧双次混合与新版算法。ComfyUI prompt ID 见 [工作流](raw-job.json)，原始正式输出见 [历史](raw-history.json)。640 × 800 合成样例中，选择中心为 (320,540)，半径 24–37 像素的绿色布料环带共 2,504 像素；指标为该带内 RGB 对原平坦布料的每通道平均绝对偏差，排除黄色部件。不是照片、纹理布料或所有修补的平均表现。

| 同候选结果 | 环带平均色差（0–255） | 选区外改变像素 | 中心残留黄色像素 |
|---|---:|---:|---:|
| 旧双次混合 | 2.144 | 0 / 507,742 | 0 |
| 新版融合 | 1.485 | 0 / 507,742 | 0 |

该样例色差降低约 31%。圆圈仍可能可见，不能宣称完全消除。见 [逐项指标](blend-metrics.json)、[旧混合](control-double-blend.png)、[新混合](new-blend.png) 和 [原始候选](candidate.png)。所有对照均保留同一生成结果，未通过换种子选择更好结果。

## 视觉复核

使用本机 RTX 5090 32 GiB、已安装的 Ollama `qwen3.6:35b-a3b`。初检只看当前多视图；独立复核同时看当前图、部件对照与历史。数量候选保留完整视图，历史对照扩大到选区周边，避免窄裁图只显示一颗纽扣后被误当成整件衣服。未下载模型，无第三方视觉 API。

新增“可能为修补痕迹”，同时记录部件证据、修正影响、与选区关系及程序计算的选区覆盖。只有表面痕迹依据、无独立部件依据、位置重叠、目标清晰且数量不矛盾时才归入痕迹。没有历史、标记框偏移、可见性不足或数量矛盾时保留“证据不足”，不会自动通过。保留原始模型判定与拦截理由，不以对象名称或圆形轮廓直接屏蔽问题。

| 最终对照 | 观察结果 |
|---|---|
| 直接适配器：旧绿色圆形残留 | 归入修补痕迹，未创建结构重绘建议；见 [报告](artifact-pilot.json) |
| 同位置真正新增黄色纽扣 | 保留 2 对 3 的结构数量差异；见 [报告](real-button-pilot.json) |
| Windows / Android 完整节点：旧修补痕迹 | 识别 surface_trace，模型框与选区不符时降为证据不足，两端无结构重绘建议；见 [Windows](windows-artifact-final.json)、[Android](android-artifact-final.json) |
| Windows 实际修正后的新版本 | 未创建结构差异建议，仍待用户核对；见 [复检](windows-recheck.json) |
| Android 实际重绘后仍存在的第三颗纽扣 | 继续报告 2 对 3，不因已有重绘历史忽略真实部件；见 [复检](android-recheck.json) |

开发中曾出现模型把放大图中的一颗纽扣当作整件衣服，错误报告缺件；保留 [调整前报告](windows-recheck-first-context.json)，随后改为当前图初检、数量完整视图和更宽历史上下文，最终结果见上表。模型仍可能数错、框错、漏检；本次不能证明这些情况已全面解决。零结构建议不等于没有修补痕迹。

## 实际界面、生成与远程边界

两端均通过实际按钮接受建议、打开选区、撤销初始框、画笔涂选、撤销重做，再提交 Qwen 25 步、denoise 1 的真实重绘。接受时任务数与素材数不增加。选区外像素、上下两颗纽扣保持原样，原图与实际选区保留，新版本替换左侧槽位，旧报告过期并阻止直接生成 3D。

- Windows：经日常 `127.0.0.1:8188`，移除了中间纽扣；选区外 507,742 像素不变。
- Android：签名 APK 安装于 Android 36 x86_64 模拟器，经原 `https://frp-rib.com:35961`、既有精确证书授权完成真实上传、生成、下载和融合；选区外 507,536 像素不变。但这次 Qwen 保留了第三颗纽扣（中心黄色 861 → 852 像素），不能宣称内容修正成功；复检仍报告真实差异。
- 正式前景 alpha 在选区内可由自动抠图重新估计；没有宣称整图 alpha 均不变。详见 [逐像素验证](verification.json)、[Windows 选区确认](windows-approval.json)、[Android 选区确认](android-approval.json)。
- 新视觉节点实际队列联调使用本次独立启动的 `127.0.0.1:8200`，手机经 `10.0.2.2:8200` 访问。日常 8188 与原外网地址仍加载旧节点，新版客户端会在上传前提示更新，不降级为单轮结果。**本次未宣称新版 V3 已在原外网完成复核；该项需日常 ComfyUI 重启后再验证。** Android 原外网地址及精确证书已恢复，见 [连接与拦截](remote-final.json)。

两端历史缩略图均加载正确，痕迹／不确定项仍需人工确认；见 [Windows 界面](windows-history-ui.png)、[Android 界面](android-history-ui.png)。合成样例主要验证颜色、部件数量、前后关系与交互，不代表真实服装／发型多视图的总体质量。模拟器验证不等于 ARM64 真机验收。
